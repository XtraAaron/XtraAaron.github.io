Portfolio Website


Description

The portfolio website is a personal project that was originally designed as a general website to display my interests and my resume. It originally started as a side project to improve my software development skills, and later developed into the primary place to display my projects.

First iteration of the website

The first iteration of the website was relativly unpolished, and was not updated frequently. It primary was a starting ground to learn the ins and outs of HTML and CSS as well as providing general coding practice. The most noteworthy features were the navigation bar, and its ability to work with multiple window sizes, albeit with major graphical bugs.

The second and current iteration of the website (as seen on the initial page) is what I have settled on. I consider it to be a much more asthetically pleasing method of displaying my projects, with significantly easier navigation and editing.


Tools Used

HTML

The backbone/structure of the website. Used for content, layout elements like headings, boxes, links.

CSS

The stylesheet, allows for further editing of the visuals/format of the website to improve asthestics.

GitHub

Used to host the website.

VS Code

Platform used to write and test the code.
       

Challenges

In the first iteration, the main challenges were getting the navigation bar to work, and making the website work on mobile browsers. The primary issue with the latter, was that it was specifically designed for my phone in particular. It broke with different website sizes, specifically for tablets and scaled computer browser windows.

The second iteration resolved the issue by foregoing the requirment entierly. Due to this, the CSS is much easier to maintain, and adding new content does not break the formatting. The navigation bar was not used due to changes in style preferences.

The primary challenge with the second website, is the sheer amount of content that now needs to be put in, a result of 2 extra years of engineering work from when the website was first created.


What I learned

The major lesson I learned from this endevor was learning about the point at which the resources invested do not justify the resulting product. Making the original website compatible for mobile did not solve any problems, rather it introduced many new ones. Changing minor things would often cause the website to break its formatting competley. This in addition to manually adjusting the spacing values, lead to a massive waste of time on my end.
